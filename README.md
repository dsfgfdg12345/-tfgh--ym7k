多门店管理与数据汇总技术实现
餐饮连锁品牌通常采用“总部+多门店”经营模式。总部需要查看所有门店菜品和订单数据汇总进行经营分析和统一管控；各门店需要独立管理本店菜品订单和营业状态不受其他门店干扰。系统必须同时满足两种需求，在数据隔离与数据聚合之间取得平衡。

每个门店拥有独立管理后台，门店账号登录后只能操作本店数据。门店可管理本店菜品（上架/下架、价格调整、库存设置）、处理本店订单（接单、叫号、完成）、查看本店经营数据（营业额、订单量、客单价）。门店后台与总部后台数据隔离，通过store_id字段实现行级权限控制。后端查询时自动附加当前登录用户所属门店的store_id条件确保门店只能看到本店数据。

多门店公用相同菜品是连锁餐饮核心需求。系统采用“总部菜品库+门店关联”设计。总部在后台维护标准菜品库包含菜品名称、图片、描述、规格、备注选项等基础信息。门店通过门店菜品关联表选择上架哪些菜品并可设置本店售价和库存。当总部修改菜品基础信息时所有关联门店菜品信息同步更新；门店独立设置的售价和库存不受影响。这种设计既保证菜品数据统一性又保留门店灵活性。

所有门店订单统一存储在订单表中通过store_id字段区分归属。门店查询订单时自动过滤本店数据；总部管理员查询时可不加store_id限制查看全部门店订单。系统提供数据汇总功能：总部后台可按时间维度（日/周/月）统计各门店营业额、订单量、热销菜品排行；可按门店维度对比经营数据；可导出报表用于财务分析。数据汇总通过聚合查询实现，利用MySQL的GROUP BY和Redis缓存提升查询性能。

门店可独立设置营业时间、休息状态和接单策略。营业时间内门店正常接收扫码点餐和外卖订单；休息状态下用户可浏览菜品但无法下单。系统支持自动接单和手动接单两种模式：自动接单模式下用户下单后系统自动接单并触发打印；手动接单需要店员在商家中心确认。订单语音提醒功能确保门店不错过任何新订单。多门店管理系统核心在于“数据隔离”与“数据聚合”的平衡，通过store_id行级权限控制、总部菜品库与门店关联分离设计以及灵活数据汇总功能，系统能够支撑连锁餐饮品牌从单店到多店规模化扩张。
